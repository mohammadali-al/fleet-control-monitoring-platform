Watchdog

Keeps a machine from hitting maximum resource use and becoming unreachable. It is a load safety net, not a tamper-proof supervisor: everything else is for the human watching this panel.

Thresholds sit above the Load Controller's operating ceiling. A Maneuver deliberately drives CPU and RAM toward its ceiling; the watchdog only acts as a backstop for load that escapes the controller, such as a runaway manual command.

The stage and the day's counters are rebuilt from the events each agent forwards (restarts and reboots taken today, the last step of the ladder, alert-only when the caps were hit); they are not read from the host, so they start empty after a server restart. The watchdog runs as its own service on each host (Restart=always, with an independent timer checking it every 45 seconds: it restarts a stopped service and one whose heartbeat has gone stale, meaning hung). Monitor agents run a headless watchdog and are not shown.

Policy profile

Version-stamped YAML, stored on the main server, pushed over the control channel and applied live without a restart.

no profile
Every key is optional; an absent key keeps the baked-in default. Raise version on every save. Per-host and per-group overrides go under overrides:. A profile that fails validation is refused here and nothing is pushed.
Hang detection. heartbeat_write is how often the watchdog and the main agent write a heartbeat (2 to 15 s). heartbeat_threshold is how old the heartbeat may get before the liveness timer restarts the service (45 to 300 s, and at least 3 times heartbeat_write). The timer itself checks every 45 s; that cadence is fixed and cannot be changed here. A value outside these limits is refused on save.

What the stored default profile resolves to (read-only). Change it in the YAML tab.

Saving pushes the new version to every connected worker agent; an agent that is offline gets it when it reconnects, and the last known profile keeps running if the main server is unreachable.
