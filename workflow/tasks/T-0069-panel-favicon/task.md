## Why

The panel has a distinctive brand mark (the `i-fleet` cube on a red tile, shown in the sidebar) but the
browser tab uses the default favicon — the SPA `index.html` (generated by `web/build.mjs`) declares no
`icon` link. Add the brand mark as a self-hosted favicon.

## What to build

1. **Favicon asset.** Create a self-hosted favicon from the brand mark: a red rounded-square background
   (the brand red — reuse the design-system accent/danger token value) with the white **`i-fleet`** cube
   glyph (`web/_src/shell.html:34`: `M12 3l8 4.5v9L12 21l-8-4.5v-9z` + inner edges) centered. Primary format
   an **SVG** (`web/assets/favicon.svg`); add a PNG fallback + an `apple-touch-icon` PNG if cheap. No
   external fetch.
2. **Wire it into the SPA head.** In `web/build.mjs` (the `<head>` it emits for `dist/index.html`), add
   `<link rel="icon" type="image/svg+xml" href="/assets/favicon.svg">` (+ the PNG/`apple-touch-icon` links).
   Keep the legacy `web/_src/shell.html` head consistent if it still ships. Rebuild the bundle
   (`./web/build.sh`) and commit the regenerated `dist/index.html` + assets.
3. **Serve it.** Ensure the favicon path is served (it's under `/assets/`, already static-served) and, if
   browsers request `/favicon.ico` at the root, either add a tiny redirect/handler in
   `internal/panel/server.go` or rely on the `<link>` — pick the simplest that avoids a 404 in the console.

## Out of scope

- No rebrand / new logo design (reuse the existing `i-fleet` mark + brand red); no changes to the sidebar
  logo or any other UI; no PWA manifest work beyond the icon link(s).

## Done means

- The browser tab shows the Fleet cube-on-red favicon on the SPA (and on refresh/deep-link); it's

  (assert the favicon asset serves 200 and the index references it); web bundle rebuilt + committed.
